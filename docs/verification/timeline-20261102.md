# step選択・物理復元・分岐記録の検証

2026-11-02。結果は[timeline-20261102.json](timeline-20261102.json)。

## 実機能と画面

- シークバー・step数字指定・1step前後・選択経路の末尾への移動。
- 選択後は停止し、手動／VLA／コードで再開できる。
- 過去から動かすと新しいbranchに記録する。元の未来のraw操作を上書きしない。
- 経路の選択で元の未来へ進み直せる。独立した新しい試行への切替とも併用できる。

IABの操作画面で元の113stepの経路をstep 50へ戻し、1step進めて51から手動操作を再開した。
Space＋Rの12stepを分岐2へ保存し、63stepまで進んだ。元の113stepの経路へ戻れることも確認した。
最終のconsoleでも数字指定でstep 80へ移動し、手動12stepで分岐2の92stepまで記録した。
元の経路の末尾113へ戻して停止している。
この操作は自動操作による`TEST_OPERATOR`であり、人の教師データとして採用していない。
画面のVLA／LLMも試験providerであり、実モデル接続の証拠ではない。

更新前の113stepの記録は別の出力先で先頭から再構築し、各stepの物理状態を完全一致で照合した。
再構築した操作は`CODE_REPLAY`で記録し、元の出所はprovenanceに保存した。

## 物理状態と再開

MuJoCo 2.3.7 / OSC_POSEでintegration state（ctrl、warmstartを含む）、OSC内部状態、
グリッパーの蓄積開閉指令、robot buffer、観測cache、乱数状態、終了flagを復元する。
保存時と同じmodel/reset・owner thread・GL contextを使う。

実simulatorを使った試験で以下を検査した。

- グリッパーを閉じている途中へ戻り、同じactionを実行した次のintegration stateがbitwise一致。
- 両カメラを新しくrenderした画素が保存時とbitwise一致。cache画像の表示だけで判定しない。
- 巻き戻し前のlease・入力を拒否し、遅れて返ったVLAの結果／未実行chunkを適用しない。
- 途中から実行したCaP-Xコードと結果は新しいbranchに保存する。
- 終了前へ戻すと終了flagが解除され、VLAで再開できる。
- 元のsteps.jsonlのSHA256が分岐前後で不変。
- 過去位置から新しい試行に移っても、元の経路と分岐のcandidate exportを残す。

分岐2を別のsimulatorで数値再生した。
親の51action＋分岐の12actionの計63actionを実行し、全64状態の最大誤差は0、手先位置誤差も0だった。
これは当該runtime・数値経路の再現性の証拠であり、タスク成功率や汎化性能ではない。
